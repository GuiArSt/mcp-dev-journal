🎫 Proposed Linear Ticket

Title: Equip Campaign AI with Image Validation Loop and Deep Context

TL;DR

The Campaign AI currently edits images blindly. If it makes a mistake (e.g., generates something weird or breaks ad rules), it doesn't know, and the user just sees a bad image. It also loses the user's original chat message in the process. We are fixing this by giving the AI a safety net: it will now automatically validate its own image edits, retry if it fails, tell the user exactly what went wrong if it can't fix it, and remember the user's exact original request for perfect traceability.

The Problem

  1. Blind Edits: The editImage tool fires and forgets. Bad edits (anatomical errors, NSFW, irrelevant outputs) are returned directly to the user without the LLM realizing it failed.
  2. Lost Intent: The original user message ("remove the cables") is lost in the metadata. We only save the LLM's rewritten prompt, making debugging hard.
note · margin These two problems look separate but share a root cause — the pipeline has no feedback loop. The model acts, and the system never asks "did that work?"

The Solution

We are closing the loop. The AI will edit the image, the system will judge it, and if it fails, the AI will retry or explain the failure to the user.

Technical Implementation

// campaign/editImage.ts — new loop
async function editImageWithValidation(input) {
  const originalIntent = input.userMessage; // preserved
  for (let attempt = 0; attempt < MAX_ATTEMPTS; attempt++) {
    const edit = await editImage(input);
    const judgment = await validateEdit(edit, originalIntent);
    if (judgment.ok) return { edit, trace: judgment };
    input = refineFromJudgment(input, judgment);
  }
  throw new EditFailure(originalIntent, attempts);
}
The point is not merely to stop bad edits. It is to make the system know it tried, how it tried, and what it owes the user when it failed.

Acceptance

  • Every editImage call is followed by a validateEdit judgment.
  • On failure, the user sees the original intent echoed, not the rewritten prompt.
  • Up to 2 retries; final failure is surfaced with a human-readable reason.
  • Full trace persisted to campaign_edits table for debugging.
